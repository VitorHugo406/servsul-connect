# Architecture rules

- Clean tab surfaces are scoped by section containers and semantic Card markers; chat, calendar, crisis screens and open task boards retain their domain presentation, while board selection uses the clean scope.
- The main shell owns tab geometry; section roots inherit its radius without an inset shell frame, preserving individual controls and domain surfaces.
- Birthday presentation separates ordinary-user upcoming name/department lists from management report controls using authenticated roles; this is a display rule, not a change to database access.
- Meeting API resources are read-only, filtered by integration companies and active rooms, with profile identities for organizers/participants; availability subtracts persisted bookings from São Paulo room hours using half-open intervals.
- Integration management uses the canonical Supabase client URL and publishable key, never separate environment-derived endpoints, to prevent preview-host requests.
- The integration base URL provides an authenticated connection confirmation; resource paths accept trailing slashes so external connector checks do not fail on URL formatting.
- No glass: bars and buttons use solid colors (src/chat-pro.css, loaded last, removes blur/sheen from every button); do not install native Expo modules in the Vite application.
- Button system (desktop): every <Button> carries `ui-btn` — 8px corners, no shadow/press-scale, sizes sm 32 / default 36 / lg 40 / icon 36; primary = company color; toggle chips use `.ui-chip` with aria-pressed; the navigation (side menu, top bar groups and their tabs) stays ROUND, never square, with a company-color active tab (rules in src/chat-pro.css).
- Desktop chat look lives in src/chat-pro.css: flat header/composer, own bubble = soft tint of the company color, consecutive messages from the same author are grouped (ChatMessage `grouped`), your own photo is never shown.
- Chat presentation uses shared semantic CSS classes and light/dark tokens across sectors, direct messages and groups, so visual changes stay consistent without changing message or permission logic.
- Chat emoji menus share a compact scrollable grid; desktop and composer menus use collision-aware portals to avoid clipping by conversation containers.
- Manual unread reminders use a shared conversation wrapper and browser storage scoped by company and profile; they never rewrite delivery receipts or other participants' read status.
- Desktop navigation measures the main page's top edge so its alignment follows header height changes.
- Vite deduplicates React and React DOM; preview development never registers a service worker, and production workers never cache development modules, to prevent mixed React runtimes after updates.- Test mode (desktop "Testar agora") swaps the shared Supabase client's methods for a localStorage store at boot, so real screens run with zero backend access; sessions expire after a fixed window and wipe their prefixed data.
- Phones (<768px) render the Ewwon mobile app (src/components/ewwon): prototype styles are scoped under `.ew`, global button glass excludes `.ew *`, data comes from the existing Supabase tables plus chat_member_prefs, user_preferences, support_tickets, chat_reactions and push_devices; the Android shell lives in capacitor/ and wraps the same dist build.
- Confirmations and text questions use appConfirm/appPrompt (src/lib/appDialog.ts, rendered by AppDialogHost on Radix Dialog) — never window.confirm/prompt/alert.
- Desktop tabs except Início and Chat use the professional look: `.pro-section` (index.css) flattens cards/buttons/tabs, PageHeader is a flat title row, and tab marks are the TabMark3D element — no emojis as tab indicators.
- Trial lifecycle: the super admin sets "Período de avaliação até" when creating a company (status trialing + trial_ends_at); the daily edge function `trial-lifecycle` (pg_cron, Vault secret) warns the company's base admin 7 days before and at expiry (access closes, status canceled, 30 days to subscribe), then 30 days later sends the super admin a Comunicados card (`ewvon-delete:<id>`, DeletionRequestCard) with two buttons; only `resolve_company_deletion` deletes data, never automatically.
- Legal/LGPD: texts live in src/lib/legal.ts (bump LEGAL.version to ask everyone to accept again); public pages /termos /privacidade /cookies /dpa; LegalGate registers acceptances in legal_acceptances (admins also accept the DPA); CookieBanner informs essential-only storage; "Meus dados e privacidade" (PC profile dialog, mobile Perfil) uses export_my_data and request_privacy_action. Until the CNPJ exists the owner appears as pessoa física (CPF and full address given in contract or on request, foro São Paulo/SP); replace with company data in LEGAL before charging customers.
- Android app (android-app/, native WebView + FCM + background service): the release APK is public/downloads/ewvon.apk; when publishing a new one, bump `version` in public/downloads/version.json (and versionName in android-app/app/build.gradle + BuildConfigVersion.java) so UpdatePrompt asks installed apps to update on open; set `required: true` to block the "later" option.
- Dash 3D (public/dash/painel.html) performance/behavior: people, chairs and desks are baked into vertex-colour meshes (`bakeVC`, `bakeFurniture`; round shapes use `DETV`), shadows refresh only when something moves, idle scenes render at 30 fps with automatic resolution, lower floors are real transparent glass with interiors built from that floor's people (`buildBelow`), walkers route around obstacles with a grid A* (`routePts`, rebuilt on every `buildWorld`), lunch seats follow the moved sofa (`loungeC`), and people with status "Em reunião" and no booking wait seated in a room (`meetCompute`). Server side, `sync_meeting_status()` (pg_cron, every minute) sets/clears "Em reunião" from room bookings and never overrides a manual status change.
