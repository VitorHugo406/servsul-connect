# Architecture rules

- Clean tab surfaces are scoped by section containers and semantic Card markers; chat, calendar, crisis screens and open task boards retain their domain presentation, while board selection uses the clean scope.
- The main shell owns tab geometry; section roots inherit its radius without an inset shell frame, preserving individual controls and domain surfaces.
- Birthday presentation separates ordinary-user upcoming name/department lists from management report controls using authenticated roles; this is a display rule, not a change to database access.
- Meeting API resources are read-only, filtered by integration companies and active rooms, with profile identities for organizers/participants; availability subtracts persisted bookings from São Paulo room hours using half-open intervals.
- Integration management uses the canonical Supabase client URL and publishable key, never separate environment-derived endpoints, to prevent preview-host requests.
- The integration base URL provides an authenticated connection confirmation; resource paths accept trailing slashes so external connector checks do not fail on URL formatting.
- No glass: bars and buttons use solid colors (src/chat-pro.css, loaded last, removes blur/sheen from every button); do not install native Expo modules in the Vite application.
- Button system (desktop): every <Button> carries `ui-btn` — 10px corners like the task-mural buttons, NEVER pill (src/styles/buttons.css, loaded last, applies the same 10px to every per-screen action/icon button, filter chip/tab and toolbar search field `dk-/tm-/sg-/bl-/ce-/wd-/wl-/wn-/mr-/mx-`; only the shell navigation and avatar buttons stay round; underlined tab bars `.gp-nav/.dk-tb/.dk-nav/.wd-tabs/.ce-tb` mark the selected tab with one straight 2px company-colour bar drawn with ::after, never a curved border), no shadow/press-scale, sizes sm 32 / default 36 / lg 40 / icon 36; primary = company color; toggle chips use `.ui-chip` with aria-pressed; the navigation (side menu, top bar groups and their tabs) stays ROUND, never square, with a company-color active tab (rules in src/chat-pro.css).
- Desktop chat look lives in src/chat-pro.css: flat header/composer, own bubble = soft tint of the company color, consecutive messages from the same author are grouped (ChatMessage `grouped`), your own photo is never shown.
- Chat presentation uses shared semantic CSS classes and light/dark tokens across sectors, direct messages and groups, so visual changes stay consistent without changing message or permission logic.
- Chat emoji menus share a compact scrollable grid; desktop and composer menus use collision-aware portals to avoid clipping by conversation containers.
- Manual unread reminders use a shared conversation wrapper and browser storage scoped by company and profile; they never rewrite delivery receipts or other participants' read status.
- Desktop navigation measures the main page's top edge so its alignment follows header height changes.
- Vite deduplicates React and React DOM; preview development never registers a service worker, and production workers never cache development modules, to prevent mixed React runtimes after updates.- Test mode (desktop "Testar agora") swaps the shared Supabase client's methods for a localStorage store at boot, so real screens run with zero backend access; sessions expire after a fixed window and wipe their prefixed data.
- Phones (<768px) render the Ewwon mobile app (src/components/ewwon): prototype styles are scoped under `.ew`, global button glass excludes `.ew *`, data comes from the existing Supabase tables plus chat_member_prefs, user_preferences, support_tickets, chat_reactions and push_devices; the Android shell lives in capacitor/ and wraps the same dist build.
- Dialogs on the PC (>=768px) open as a full-height SIDE PANEL on the right (owner's request, "like Meu Perfil but taller"): src/components/ui/dialog.tsx sets `data-side` on every DialogContent except `ewvon-profile-drawer`, `gs-dlg` (Ctrl+K) and anything with the class `ui-center` (command palette, VideoCallHost); buttons.css positions it (top/right/bottom 12px, 20px radius, slide-in, `max-height`/`height` overridden, own `max-w-*` kept, horizontal overflow hidden, children `min-width:0` so long titles never cause a side scroll) and gives the overlay a light 2px blur (`.ui-side-overlay`). Right/left `SheetContent` (Score, filters, automations, notifications, chat media…) get the same floating look on the PC (`data-ui="sheet"` `data-panel`, 12px from the edges, rounded, `.ui-side-overlay`). Phones keep centred dialogs. New dialogs get this automatically; add `ui-center` only for things that must stay centred (calls, palettes, and the open card — TaskDetailDialog desktop (`.tdx`, buttons.css: centred, min(1160px, 92vw) × 86vh, rectangular) has two calm columns: card content (ONE row of actions — Etiquetas, Datas, Checklist, Membros, Capa, Prioridade, Mais; Decisões lives inside "Mais" (owner, so the row never wraps), templates keep the Decisões button because they have no "Mais" — below it, `.tdx-top` = Detalhes and Campos as collapsible boxes that open CLOSED like the checklists (`detOpen`/`fldOpen` reset per task; closed header shows a one-line summary: column + due tag / "x/y preenchidos") — Detalhes (Situação = column, Entrega + late/soon/done tag, Responsável, Checklist ring; Notion-like `.tdx-prop` rows) and Campos side by side (one column when the mural has no fields), then FULL WIDTH Descrição, Decisões, Checklist, then Dependências, Links, Tempo, Aprovação (`CardExtrasPanel only="fields"|"rest"`); no status chips above the title; the cover stays full width on top and the comments/activity column runs from the cover down to the footer (title, labels and actions only on the left), dependency chips/buttons 8px corners — every subject in its own bordered box `.tdx-box` on a light grey canvas (`.tdx-canvas`); the header (`.tdx-head`) is a soft band in the colour of the card's column with chips: column, due date (red late / amber ≤2 days / green done, with "N dias de atraso" / "Faltam N dias") and checklist progress ring; checklists open CLOSED every time a card is opened (effect keyed by task id, kept above the early return) (aside children are boxed automatically), empty subjects show no box) on the left and comments/activity on a tinted 380px column on the right, no stacked dividers).
